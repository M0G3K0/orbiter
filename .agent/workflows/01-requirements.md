# 📝 Phase 01: Requirements（要件の整理）

ユーザーの「作りたい」を**会話で引き出し**、
02 IA Explore に渡せる形に構造化する。

> ⚠️ **最初からガチガチに決めない**。
> ユーザーはざっくりした一言から始めていい。
> AIが対話の中で足りない情報を自然に聞き出し、一緒にブラッシュアップする。

---

## 💬 Step 1: 会話で引き出す

ユーザーの最初のインプットがどんな粒度でも受け取る。

```
「検索画面を作りたい」         ← これでOK
「TOPページをリニューアルしたい」 ← これでOK
「なんかいい感じにしたい」      ← これでもOK
```

AIは以下の**ゴール項目**を意識しながら、自然な会話の中で不足を埋めていく。
一問一答ではなく、文脈に合わせて聞く。

### 🎯 ゴール項目（AIが内部的に意識する）

| 項目 | なぜ必要か |
|------|-----------|
| **何を作るか** | IA Explore で画面構成を考えるために必要 |
| **誰が使うか** | インターフェースの複雑さ・言葉遣いが変わる |
| **一番大事なこと** | 複数パターンの評価軸になる |
| **制約** | 使える部品・避けるべきパターンが変わる |
| **参考プロダクト** | IA Explore でのパターン探索の起点になる |

> 💡 ユーザーが「わからない」と言った項目は空欄のまま進めてOK。
> IA Explore で複数パターンを出す中で見えてくることもある。

---

## 📝 Step 2: 構造化（AIが作成）

会話が十分にまとまったら、AIが以下のサマリーを作成してユーザーに確認する。

```
## 📝 Requirements Summary

- **作るもの**: (1〜2文で)
- **ユーザー**: (誰がどういう状況で使う)
- **Core Value**: (一番大事なこと)
- **制約**: (守らないといけないこと)
- **参考**: (似てるもの)
- **未確定**: (まだ決まっていないこと → IA Explore で検討)
```

> 📌 **未確定** の項目が重要。
> ここが IA Explore で「AIが複数パターンを出して一緒に決める」部分になる。
